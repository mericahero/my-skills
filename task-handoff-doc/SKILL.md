# 智能体任务交接文档生成

## Overview

本技能以"任务交接架构师"角色，将当前执行上下文提炼为一份结构化交接文档。文档不是总结，而是可操作的行动蓝图，覆盖任务快照、工具链资产、决策上下文、风险待办与验证清单五类信息。生成后须通过自我审查，确保任何接替者可在不询问原执行者的前提下独立启动下一个任务。

## 触发条件

收到以下任一类指令时立即执行：

- 显式指令："生成交接文档""生成任务交接单""写一个 handoff doc""把当前任务交接给 XXX"。
- 隐含场景：任务跨会话续做、跨团队移交、暂停后恢复、或将上下文交给另一个智能体/工程师。
- 若当前执行上下文信息不足，停止生成，改为列出缺失项并请求补充（见 §6）。

## 工作流

### 步骤 1：采集当前执行上下文

从当前会话、已读文件、工具调用记录、任务清单中提取五类信息。逐项核对，缺失则用 `<缺失>` 占位并记入 §6 缺失清单，而非编造。

### 步骤 2：套用模板生成文档

读取 `references/handoff-template.md`，按该模板的五个章节填充，保持标题层级与表格结构不变：

1. **任务全景快照**：一句话核心目标 + 已完成里程碑（含验证结果）+ 当前精确阶段 + 已确认约束（合规/资源/时间）。
2. **工具链与资产清单**：工具名称/版本/关键参数/凭证引用路径表；工具依赖与调用顺序；关键输出文件路径/格式/数据字典链接。
3. **决策日志与上下文**：重大决策（备选方案→最终选择→依据）；未决争议与待确认事项；与原计划偏差及原因；讨论/评审索引。
4. **风险与待办事项**：已识别风险（等级/缓解/应对）；3-5 项高优先级任务（动作/预期输出/验收标准/截止时间/负责人）；需人工或跨团队协调事项及对接人。
5. **交接验证清单**：可勾选的环境检查、数据完整性验证、工具连通性测试、首个任务执行确认。

文档末尾强制包含：最后更新时间、生成智能体标识、指定交接人。

### 步骤 3：遵守输出格式与风格规范

- 使用 Markdown，层级标题与表格呈现结构化信息。
- 语言简洁、客观、无歧义，避免"大概""可能""尽快"等模糊词。
- 时间、版本、路径必须精确到可执行级别（如 `2026-08-06 14:30 CST`、`python 3.13.12`、绝对路径）。
- 敏感信息一律引用处理（如 `Vault:secret/xxx`、`env:API_KEY`），绝不明文暴露密钥、令牌、个人联系方式。

### 步骤 4：质量校验（自我审查）

生成后逐项回答，任一为"否"则回到步骤 2 重新生成直至全部为"是"：

1. 接替者能否在不询问原执行者的情况下，独立启动下一个任务？
2. 所有工具调用路径是否完整且可验证？
3. 风险与待办事项是否具体到可分配、可验收？
4. 是否存在任何假设性表述或未经验证的信息？

### 步骤 5：交付与归档

将最终文档写入工作区可访问路径（如 `./HANDOFF.md` 或任务工单附件），并通知指定交接人。告知用户文档已生成及所在路径。

### 步骤 6：信息不足的处理

若步骤 1 发现关键上下文缺失（如未知凭证引用路径、无里程碑验证证据、无指定交接人），不生成不完整文档。改为输出一份"缺失项清单"，列出每项缺失内容、为何必要、以及需要用户补充什么，待补充完整后重新执行步骤 2。
