# 基于交接文档续做（Handoff Resume）

## Overview

本技能赋予智能体"消费"一份交接文档的能力。文档由 `task-handoff-doc` 技能产出，包含 §1 任务快照、§2 工具链、§3 决策日志、§4 风险待办、§5 验证清单。智能体据此先验证现状、再执行任务、最后回写状态，使任务可在会话间、智能体间、人机之间无缝续接。文档是单一事实来源。

## 触发条件

收到以下任一类指令时执行：

- 显式："基于交接文档继续""接着做交接文档里的任务""按交接单执行下一步""resume from handoff"。
- 隐含：任务从上一会话/上一智能体接手续做；或用户给出一份 `HANDOFF.md` 要求接着干。
- 若未提供文档路径，先询问；不要凭空假设任务内容。

## 工作流

### 步骤 1：定位并解析文档

- 默认路径 `./HANDOFF.md`，或用户指定路径。找不到则停止并报告，不假设。
- 运行 `scripts/parse_handoff.py <doc>` 得到结构化 JSON（tasks / verification / tools / metadata），作为执行视图。
- 详尽的章节→动作映射见 `references/resume-guide.md`，执行前先读。

### 步骤 2：跑 §5 验证门禁

- 对解析出的 verification 项逐项执行：环境版本比对、数据文件存在性与行数/哈希校验、§2 工具连通性探测、§4 序号1 首个动作试执行。
- 将每项结果回填为 `- [x]` / `- [ ]`。
- **门禁规则**：任一关键项 fail 即停止续做并报告，带病不开工；失败原因记入 §4 风险或 §3 未决事项。

### 步骤 3：解析凭证引用（安全红线）

- 从 §2"凭证引用路径"解析：`env:XXX` 读环境变量、`Vault:secret/xxx` 调密钥系统，**绝不明文输出**。
- 解析失败视为 §5 门禁失败，停止并上报。

### 步骤 4：按序执行 §4 任务

对任务表逐行：

1. 解析动作/预期输出/验收标准/截止/负责人。
2. 负责人为自身 → 调用 §2 工具（按依赖顺序）执行，产生预期输出。
3. 把"验收标准"转为可判定条件（文件存在、行数相等、含关键词等）自验。
4. 通过则标记完成；不通过应用 §4 对应风险的"触发时应对"（如回滚）。
5. 临近/超截止时间则优先并提示。

### 步骤 5：处理人工/跨团队事项

- §4 中标注"需人工介入 / 跨团队协调"的项：**不自主决策**，暂停并通知文档末尾"指定交接人"，说明事项、对接人、所需决策、期望时间。
- 收到反馈后作为新决策回写 §3，再继续。

### 步骤 6：回写文档

就地更新文档以保最新：§3 追加决策与偏差、§5 更新勾选、末尾刷新"最后更新时间"与"生成智能体标识"。文档若入库则修改该文件，使下一棒直接续接。

### 步骤 7：续做循环

完成一个 §4 任务后自动进入下一个，直到全部完成或被阻塞。每个续接方都从 §5 重新验证再开工。

## 边界与异常处理

- **信息不足**：§4 缺可验证验收标准或 §2 缺凭证引用 → 停止并列出缺失项，请用户补充，不猜测执行。
- **文档与现状冲突**：以 §5 验证结果为准，冲突记入 §3 未决事项，不默默按错误前提执行。
- **多智能体接力**：文档即接力棒，每棒先验证后开工。

### scripts/

- `parse_handoff.py` — 将交接文档解析为 JSON（`python parse_handoff.py <doc> [--pretty]`）。输出 tasks / verification / tools / decisions / risks / metadata，供智能体结构化消费。

### references/
