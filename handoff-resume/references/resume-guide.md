# 续做指引：智能体如何消费交接文档

本指引配合 `task-handoff-doc` 生成的文档使用。目标：让 AI 智能体在不询问原执行者的前提下，独立验证现状并推进 §4 任务。文档是**单一事实来源（single source of truth）**，任何状态变化都必须回写文档。

## 0. 定位文档

- 默认路径：`./HANDOFF.md`，或用户显式指定。
- 找不到时：**停止**，向用户报告缺失路径，不要凭空假设任务内容。
- 可用 `scripts/parse_handoff.py <doc>` 将文档解析为 JSON，作为结构化视图消费。

## 1. 解析与读档

用解析脚本或按章节标题（## 1. ~ ## 5.）定位：

| 章节 | 智能体动作 |
|------|-----------|
| §1 任务全景 | 确认接手时处于哪个阶段；读"阶段判定依据"以理解如何客观验证阶段。 |
| §2 工具链 | 提取工具名/版本/参数/凭证引用；建立调用顺序图。 |
| §3 决策日志 | 理解历史选型与未决事项，避免推翻已有决策或重蹈覆辙。 |
| §4 风险待办 | 提取任务表（动作/预期输出/验收标准/截止/负责人）与风险表。 |
| §5 验证清单 | 提取可勾选项，作为开工前的门禁。 |

## 2. §5 验证门禁（开工前必须全绿）

逐项执行并判定 pass/fail，将结果回填为 `- [x]` / `- [ ]`：

- **环境检查**：比对当前运行时版本与 §2（如 `python --version` 是否 3.13.12）。
- **数据完整性**：§2 输出文件是否存在；行数/哈希是否与文档记录一致。
- **工具连通性**：对 §2 各工具跑健康检查（如接口 ping、最小查询）。
- **首个任务确认**：执行 §4 序号 1 的第一个动作，产出是否符合验收标准。

**门禁规则**：任一关键项 fail，停止续做并报告，不要带病开工。失败原因记入 §4 风险或 §3 未决事项。

## 3. 凭证解析（安全红线）

- §2"凭证引用路径"只可能是引用形态：`env:XXX`、`Vault:secret/xxx`、凭据管理器条目 ID。
- 解析方式：
  - `env:XXX` → 读取环境变量 `XXX`，绝不回显。
  - `Vault:secret/xxx` → 调密钥管理系统 API 按路径读取。
- **严禁**在对话、日志、回写文档中输出明文密钥/令牌。
- 引用解析失败 = §5 门禁失败，停止并上报。

## 4. 执行 §4 任务

按序号顺序逐个消费任务行：

1. **解析**：动作 → 预期输出 → 验收标准 → 截止时间 → 负责人。
2. **判定归属**：负责人为 `agent`/自身 → 自主执行；标注"需人工介入" → 跳过，转入 §6。
3. **执行**：调用 §2 工具（按依赖顺序），产生预期输出。
4. **自验**：把"验收标准"转为可判定条件（文件存在、行数相等、内容含关键词等）。通过则标记任务完成；不通过则应用 §4 对应风险的"触发时应对"（如回滚）。
5. **时限**：比对截止时间；临近或超期则优先并提示。

## 5. 回写（保持文档最新）

每完成一个任务或发生偏差，更新文档原位：

- §3 决策日志：追加新决策（备选→选择→依据）。
- §3 偏差表：记录与计划的偏差及原因。
- §5 验证项：更新勾选状态。
- 文档末尾：更新"最后更新时间"与"生成智能体标识"。
- 若文档入库（git 等），就地修改该文件，使下一棒直接续接。

## 6. 人工/跨团队事项

- §4 中"需人工介入 / 跨团队协调"项：**不自主决策**，暂停并通知"指定交接人"（§末尾字段）。
- 通知内容：事项、对接人、所需决策、截止期望。
- 收到人类反馈后，将其作为新决策回写 §3，再继续。

## 7. 边界与异常处理

- **文档信息不足**：若 §4 任务缺少可验证的验收标准，或 §2 缺凭证引用，停止并列出缺失项，请用户补充——不要猜测执行。
- **文档与现状冲突**（如 §2 凭证路径已失效）：以 §5 验证结果为准，冲突记入 §3 未决事项，不要默默按错误前提执行。
- **续做循环**：完成一个 §4 任务后自动进入下一个，直到全部完成或被阻塞。
- **多智能体接力**：每个智能体都从 §5 重新验证再开工，文档即接力棒。
